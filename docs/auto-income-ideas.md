# Python + VPS + Claude Code で完全自動運用できる収益源 — 比較と設計

**前提となる考え方**: ポイ活のシミュレーションで得た結論をそのまま使う。

> **自動化はボトルネックを消さない。移動させるだけ。**

ポイ活では、AIの精度でも無料枠でもなく「申込ペース制限」が律速だった。
同じ問いを他のビジネスに当てると、**ほぼ全ての律速は「集客」**になる。
したがって「完全自動で収益」を成立させるには、次のどれかを選ぶしかない。

| 型 | 構造 | 例 |
|----|------|-----|
| **A. 集客不要型** | 自分の資産・資金だけで完結する | 自動売買、ポイント資産運用 |
| **B. 集客を借りる型** | プラットフォームが客を連れてくる | マーケットプレイス出品、ストア公開 |
| **C. 集客を自動化する型** | 検索流入で客が来る | 自動更新データサイト |
| ~~D. 労働置換型~~ | 自動化しても人間の稼働が要る | 受託、代行 → **対象外** |

---

## 1. 候補の比較

「運用労力」は立ち上げ後に毎月かかる時間。ここがゼロに近いものだけを候補にしてある。

| # | 案 | 型 | 初期労力 | 運用労力 | 立ち上がり | 月次見込み（安定後） | 法的リスク |
|---|-----|----|---------|---------|-----------|------------------|----------|
| 1 | **監視・通知マイクロSaaS** | B/C | 2〜3週 | **~0.5h** | 3〜6ヶ月 | ¥3,000〜50,000 | 低 |
| 2 | **APIマーケットプレイス出品** | B | 1〜2週 | **~0h** | 1〜3ヶ月 | ¥0〜30,000 | 低 |
| 3 | **買い切りテンプレート販売** | B | 2週 | **~0h** | 1〜2ヶ月 | ¥4,000〜80,000 | 低 |
| 4 | **ニッチ自動更新データサイト** | C | 3〜4週 | ~1h | 6〜12ヶ月 | ¥0〜30,000 | 中（引用範囲） |
| 5 | ポイント資産運用（設計済み） | A | 1週 | ~0.2h | 即日 | ¥3,000〜10,000 | 低 |
| 6 | 自動売買の横展開（既存） | A | — | ~1h | — | 変動（元本リスク） | 低 |

**正直に言っておくべきこと**: 「労力をかけずに」は**運用フェーズについては本当**だが、
**初期構築には2〜4週間の人間の労力が必ず要る**。完全自動なのは作り終えたあとの話で、
作る工程そのものは自動化できない。ここを混同すると必ず期待外れになる。

## 2. 本命: 監視・通知マイクロSaaS

**推す理由は「新しく学ぶことがほぼ無い」から。** BTC自動売買で既に持っている資産がそのまま使える。

| 既にあるもの | そのまま流用できる先 |
|-------------|------------------|
| ConoHa VPS + systemd | 監視ジョブの常駐・定期実行 |
| 定期実行 + ログ + 状態ファイル | 巡回・差分検知・再送防止 |
| 通知処理 | ユーザーへの配信 |
| Claude Code (headless) | **新しい監視対象の追加を数十分で終わらせる** |

### 何を監視するか

「公開されているが、変化を見張るのが面倒」なものを選ぶ。条件は3つ:

1. 公開情報である（ログイン不要・robots.txt で許可されている）
2. 変化が不定期で、見逃すと損をする
3. 見張っている人が一定数いるが、専用ツールが無い

具体例:

| 対象 | 課金しやすさ | 備考 |
|------|------------|------|
| 補助金・助成金の公募開始 | 高 | 事業者は取り逃しの損失が大きい |
| 自治体施設・キャンプ場等の予約枠の空き | 高 | キャンセル拾いの需要が強い |
| 特定カテゴリの中古市場の出物 | 中 | 通知の速さが価値になる |
| 学会・研究費の公募 | 中 | ニッチだが確実な需要 |
| 特定分野の求人・入札情報 | 中 | 更新頻度が低く巡回コストが安い |

**選び方のコツ**: 自分が実際に見張っていて面倒だと思っているものを選ぶ。
自分がユーザー第1号でないと、通知の質を判断できない。

### 収益モデル

```
無料プラン: 監視1件・通知は1日1回まとめ
有料プラン: 月¥480 — 監視10件・即時通知・条件フィルタ
```

**最初から課金しない。** 半年は無料公開してユーザーを集め、
「もっと監視枠が欲しい」という声が出てから課金を足す。
先に課金導線を作ると、集客と課金の両方を同時に検証することになり、失敗の原因が切り分けられない。

### アーキテクチャ（既存の流儀を踏襲）

```
/opt/watcher/
├── systems/
│   ├── crawl.py        # 監視対象を巡回（robots.txt 尊重・間隔3秒以上）
│   ├── diff.py         # 前回との差分検知（状態ファイルで再送防止）
│   ├── filter.py       # ユーザーごとの条件マッチ
│   └── notify.py       # 配信
├── config/
│   ├── targets.yaml    # ★監視対象の定義。Claude Code がここを増やす
│   └── users.yaml
├── data/watcher.db
└── logs/
```

`targets.yaml` を宣言的にしておくのが肝。新しい監視対象の追加が**設定ファイルの追記**で済み、
Claude Code に「このURLを監視対象に追加して」と頼むだけで増える。

```yaml
- id: subsidy_tokyo
  url: https://example.go.jp/subsidy/list
  interval_min: 60
  selector: "table.list tr"
  key_fields: [title, deadline]
  notify_when: new_row
```

### 守るべきこと

- **robots.txt を尊重し、1リクエスト3秒以上の間隔を空ける。** 相手のサーバーに負荷をかけない
- **取得したデータをそのまま再配布しない。** 「変化があった」という事実と元URLを通知する
- User-Agent に連絡先を明記する
- 利用規約でクローリングを禁止しているサイトは対象にしない

## 3. 次点: APIマーケットプレイス出品

**集客をプラットフォームに完全に任せられる**のが最大の利点。デプロイしたら本当に何もしない。

置くもの: 「あると便利だが、自分で書くほどではない」小さな処理。

- 日本の営業日・祝日計算（振替休日・年末年始対応）
- 住所の正規化・都道府県分割
- 特定フォーマットの相互変換
- 軽量なテキスト整形・バリデーション

```
FastAPI + VPS で1エンドポイント → マーケットプレイスに出品 → 月$5〜$30 のプラン
```

**期待値は正直に言って低い**（多くの出品は月$0）。ただし
**初期労力1〜2週間・運用労力ゼロ**なので、外れても損失が時間だけで済む。
複数出しておいて当たりを待つ性質のもの。

## 4. 実績を売る: 買い切りテンプレート販売

**あなたの一番の資産は「VPS上でPythonの自動売買を実運用している」という事実**で、
これは記事にもテンプレートにもなる。実運用していない人が書いたものとは中身が違う。

売れる形:

- 「ConoHa VPS + systemd + Python で自動売買botを24時間動かす」構成テンプレート一式
- Claude Code を cron から headless で回して自己修復させる運用パターン
- バックテスト → シャドウ運用 → 本番投入の検証フロー

買い切り ¥2,000〜5,000。作ってしまえば運用労力ゼロ。

**注意**: 具体的な売買ロジックや「勝てる設定」を売る形にすると、
**金融商品取引法の投資助言・代理業に該当する可能性がある**（無登録営業は違法）。
売るのは**インフラ構成・運用手法・検証手順**に限り、銘柄推奨や具体的な売買判断は含めない。

## 5. 提案しないもの

| やらない | 理由 |
|---------|------|
| 投資シグナル配信・有料サロン | 金商法の投資助言に該当しうる。無登録営業は違法 |
| AI生成コンテンツの大量投稿 | 検索エンジンのスパムポリシー違反。アカウント停止リスク |
| スクレイピングしたデータの再配布 | 著作権・利用規約違反 |
| ポイントサイトのアンケート自動回答・広告自動クリック・アプリ自動起動 | 広告主は「実在の人間が実際に見た・使った・答えた」ことに対価を払っている。自動化はその前提を崩すため、規約違反にとどまらない。加えてアンケートは市場調査データそのものを汚染する。実利面でも行動ログ・端末指紋・注意チェックで検出され、没収・凍結に至る |
| 他人のアカウントを操作する自動化 | ほぼ全サービスの規約違反 |

## 6. 最初の2週間の計画（案1を選んだ場合）

| 日 | やること |
|----|---------|
| 1〜2 | 自分が実際に見張っていて面倒なものを3つ挙げ、robots.txt と利用規約を確認 |
| 3〜5 | `crawl.py` + `diff.py` + 状態ファイル。**まず自分専用**に1対象だけ動かす |
| 6〜7 | systemd timer 化。BTC botと同じ VPS に同居（追加費用ゼロ） |
| 8〜10 | `targets.yaml` を宣言的に。Claude Code で対象を3つに増やせることを確認 |
| 11〜12 | 通知の質を自分で1週間使って調整（誤検知・重複・通知過多） |
| 13〜14 | 無料公開。登録フォームだけ用意して、使う人がいるかを見る |

**判断基準**: 2週間後に「自分が毎日使っているか」。使っていないなら他人も使わない。
その場合は監視対象を変えるか、案2・案3に移る。

## 7. 全案に共通する運用の型（既存資産の流用）

```
systemd timer で定期実行
    ↓
状態ファイルで冪等性を担保（再送・二重実行の防止）
    ↓
CSV/SQLite に実績を記帳
    ↓
Claude Code (cron, headless) が日次レポートを生成
    ↓
壊れたら Claude Code が自己修復して PR を作る
```

BTC自動売買で既に回っている型をそのまま横展開できる。
**新しい収益源を足すたびに、この型を1つコピーするだけで済む**ようにしておくのが、
「少額でも積み重ねる」を実際に積み重ねられる形にするための条件。
