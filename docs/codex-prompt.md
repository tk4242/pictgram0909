# Codex に渡すプロンプト集

Codex（`codex` CLI / Codex Web）に貼り付けて使うプロンプトです。
そのままコピペしてください。`<>` の部分だけ書き換えます。

Claude Code 側に同じ役割を振るときは、`Codex` → `Claude Code`、
`codex/` → `claude/` に読み替えてください。

---

## 1. 初回セットアップ（最初の 1 回だけ）

```text
このリポジトリは Codex と Claude Code の 2 つの AI が同じファイルを触る前提で運用しています。

まず AGENTS.md を最初から最後まで読んでください。これが唯一の情報源です。
CLAUDE.md は AGENTS.md を参照するだけの薄いファイルなので、ルールを変えるときは
AGENTS.md だけを編集してください。

読み終えたら、以下を私に報告してください。

1. あなたが守るべきブランチ運用のルール（1〜2 行で）
2. このリポジトリで実行できる検証コマンド
3. この環境で bundle install が通るかどうか（実際に `bundle check` を実行して確認）
4. AGENTS.md §8「既知の問題」のうち、あなたが最も優先度が高いと考えるものとその理由

まだコードは変更しないでください。読んで報告するだけです。
```

## 2. 実装タスクを依頼するとき

```text
【タスク】
<やってほしいことを具体的に>

【守ること】
- 事前に AGENTS.md を読むこと
- 作業開始前に `git fetch origin && git checkout master && git pull origin master` を実行すること
  （Claude Code が先に push している可能性があります）
- ブランチは `codex/<内容>` を切ること。master に直接コミットしないこと
- 依頼していない箇所は直さないこと（AGENTS.md §8 の既知の問題も、指示がなければ触らない）
- コミットメッセージ末尾に `Co-Authored-By: Codex <codex@openai.com>` を入れること

【報告に必ず含めること】
1. 変更したファイルと変更の意図
2. 実際に実行した検証コマンドとその結果（成功/失敗）
3. 実行できなかった検証と、その理由
4. 判断に迷った点（Claude Code に見てほしい箇所）

テストを実行していないのに「動作確認済み」と書かないでください。
実行できなかったなら「テスト未実行」と正直に書いてください。

完了したら `git push -u origin codex/<内容>` してブランチ名を教えてください。
PR は私が指示するまで作らないでください。
```

## 3. Claude Code の作業を検証させるとき（相互検証）

```text
Claude Code が実装した内容をあなたに検証してほしいです。

【対象ブランチ】claude/<内容>

【手順】
1. AGENTS.md を読む（特に §7「AI 間の相互検証プロトコル」）
2. `git fetch origin`
3. `git diff master...origin/claude/<内容>` で差分を全部読む
4. この環境で実行できる検証コマンドを実際に走らせる

【チェック項目】AGENTS.md §7 のチェックリストを 1 項目ずつ潰してください。
- binding.pry / debugger / デバッグ用 puts が残っていないか
- テストが変更に追随しているか
- ルーティングヘルパー名が config/routes.rb と一致しているか
- Strong Parameters を通しているか
- db/schema.rb とマイグレーションの整合が取れているか
- Claude Code の「検証済み」という主張が、実際に実行可能なものだったか

【報告の形式】
- 確認できた項目
- 問題が見つかった項目（該当ファイルと行番号つき、なぜ問題かを具体的に）
- 確認できなかった項目（理由つき）

「LGTM」だけの回答は禁止です。何を見て問題なしと判断したのかを書いてください。
Claude Code の報告を鵜呑みにせず、自分で実行して確かめてください。
この段階ではコードを修正せず、指摘を返すだけにしてください。
```

## 4. VPS（リモートサーバ）を操作させるとき

```text
【接続先】ssh -i ~/.ssh/id_ed25519 root@160.251.137.210

【タスク】
<やってほしいことを具体的に>

【守ること】AGENTS.md §6 を先に読んでください。特に:
- root 接続なので、打ったコマンドは即座に本番へ効きます。取り消せません
- 触る前にまず読む（ls -la / stat / journalctl で現状把握）
- 最終更新日時が想定と違う場合は Claude Code が変更した可能性があります。
  上書きせず、まず私に報告してください
- ファイル編集前に必ずバックアップ:
  `cp <file> <file>.bak.$(date +%Y%m%d_%H%M%S)`
- 編集後は必ず `python3 -m py_compile <file>` を通すこと
- 以下は私の明示的な指示があるまで実行禁止:
  サービス再起動 / stop、pip install、apt install、rm、kill、
  cron・systemd timer の変更、ファイアウォール・SSH 設定の変更、
  運用設定値（金額・閾値・API キー）の変更
- 読み取り専用コマンド（cat, ls, tail, journalctl, grep, ps, df）は確認不要です

【報告に必ず含めること】
1. 実行したコマンドをそのまま（要約せず、実際に打った文字列で）
2. 変更したファイルとバックアップ先のパス
3. 構文チェック・動作確認の結果
4. サービスを再起動したかどうか（していなければ「未反映」と明記）

秘密鍵や API キーの中身は絶対に出力しないでください。
```

## 5. VPS 上の変更を検証させるとき

```text
Claude Code が VPS 上で行った変更を検証してください。

【接続先】ssh -i ~/.ssh/id_ed25519 root@160.251.137.210
【対象ファイル】<パス>

【手順】読み取りのみ。何も変更しないでください。
1. `ls -la <ディレクトリ>` でバックアップファイルの有無と最終更新日時を確認
2. `diff <file>.bak.<タイムスタンプ> <file>` で差分を確認
3. `python3 -m py_compile <file>` で構文確認
4. `journalctl -u <サービス名> -n 100 --no-pager` で変更後の挙動を確認

バックアップが存在しない場合は「検証不能」として差し戻してください。
バックアップを取らずに本番を編集したこと自体が指摘対象です。

【報告】差分の内容、構文チェック結果、ログ上の異常の有無、
そして変更がサービスに反映済みかどうかを書いてください。
```

## 使い方のコツ

- **同じファイルを 2 つの AI に同時に編集させない。** 片方が push → もう片方が
  `git fetch` してから着手、の順番を守るとコンフリクトがほぼ起きません。
- **実装した AI に自分の作業を検証させない。** 必ずもう一方に見せてください。
  自己検証は「問題なし」に流れやすく、相互検証の意味がなくなります。
- **報告フォーマットを毎回同じにする**と、2 つの AI の出力を並べて比較しやすくなります。
